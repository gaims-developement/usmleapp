# Forum System - Implementation Plan

## Architecture Audit Summary

| Aspect | Current State |
|--------|---------------|
| Database | MySQL 8 via MariaDB driver adapter, Prisma ORM |
| Backend | Express 5 (ESM JavaScript), Zod validation |
| Frontend | React 19 + TypeScript + Vite 8, React Query, Tailwind CSS v4 |
| Auth | JWT access tokens (15min) + refresh tokens, `authenticate` middleware |
| RBAC | 6 roles (SUPER_ADMIN, ADMIN, REVIEWER, HOSPITAL, DOCTOR, STUDENT), 19 permissions, hierarchy (SUPER_ADMIN supersedes ADMIN) |
| Storage | Cloudinary (prod) or local filesystem (dev), `storageService` factory |
| Notification | `Notification` model in DB, `notify()` helper in `notification.routes.js` |
| UI Components | Custom design system: Button, Card, Input, Select, PageHeader, EmptyState, Modal, Toast, Spinner, StatusBadge, etc. |
| Nav | Per-role nav config arrays in `*-nav.ts` files, rendered by `AppLayout` |
| Existing Forum Code | None |

### 1.1 Prisma Schema Additions

Add 8 new models + 3 new enums to `prisma/schema.prisma`:

```prisma
enum ForumPostType {
  DISCUSSION
  QUESTION
  EXPERIENCE
  RESOURCE
  CLINICAL_CASE
  HOSPITAL_REVIEW
}

enum ForumPostStatus {
  PUBLISHED
  HIDDEN
  DELETED
}

enum ForumReportReason {
  SPAM
  HARASSMENT
  MEDICAL_MISINFORMATION
  OFFENSIVE_CONTENT
  ADVERTISING
  PERSONAL_INFORMATION
  OTHER
}

enum ForumReportStatus {
  PENDING
  RESOLVED
  DISMISSED
}

model ForumCategory {
  id          String   @id @default(cuid())
  name        String   @unique
  slug        String   @unique
  description String?
  isActive    Boolean  @default(true)
  sortOrder   Int      @default(0)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  posts ForumPost[]

  @@index([isActive])
  @@index([sortOrder])
}

model ForumPost {
  id          String           @id @default(cuid())
  authorId    String
  author      User             @relation(fields: [authorId], references: [id], onDelete: Cascade)
  categoryId  String
  category    ForumCategory    @relation(fields: [categoryId], references: [id], onDelete: Restrict)
  title       String           @db.VarChar(200)
  content     String           @db.Text
  postType    ForumPostType    @default(DISCUSSION)
  status      ForumPostStatus  @default(PUBLISHED)
  upvoteCount Int              @default(0)
  commentCount Int             @default(0)
  createdAt   DateTime         @default(now())
  updatedAt   DateTime         @updatedAt

  attachments ForumPostAttachment[]
  comments    ForumComment[]
  reactions    ForumReaction[]
  bookmarks    ForumBookmark[]
  reports      ForumReport[]

  @@index([authorId])
  @@index([categoryId])
  @@index([createdAt])
  @@index([status])
  @@index([postType])
}

model ForumPostAttachment {
  id             String  @id @default(cuid())
  postId         String
  post           ForumPost @relation(fields: [postId], references: [id], onDelete: Cascade)
  storageProvider String
  url            String  @db.Text
  publicId       String?
  fileName       String
  mimeType       String
  fileSize       Int
  createdAt      DateTime @default(now())

  @@index([postId])
}

model ForumComment {
  id           String             @id @default(cuid())
  postId       String
  post         ForumPost          @relation(fields: [postId], references: [id], onDelete: Cascade)
  authorId     String
  author       User               @relation(fields: [authorId], references: [id], onDelete: Cascade)
  parentId     String?
  parent       ForumComment?      @relation("CommentReplies", fields: [parentId], references: [id], onDelete: Cascade)
  replies      ForumComment[]     @relation("CommentReplies")
  content      String             @db.Text
  status       String             @default("PUBLISHED")
  upvoteCount  Int                @default(0)
  createdAt    DateTime           @default(now())
  updatedAt    DateTime           @updatedAt

  reactions  ForumReaction[]
  reports    ForumReport[]

  @@index([postId])
  @@index([authorId])
  @@index([parentId])
  @@index([createdAt])
}

model ForumReaction {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  postId    String?
  post      ForumPost? @relation(fields: [postId], references: [id], onDelete: Cascade)
  commentId String?
  comment   ForumComment? @relation(fields: [commentId], references: [id], onDelete: Cascade)
  type      String   @default("UPVOTE")
  createdAt DateTime @default(now())

  @@unique([userId, postId, type])
  @@unique([userId, commentId, type])
  @@index([postId])
  @@index([commentId])
  @@index([userId])
}

model ForumBookmark {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  postId    String
  post      ForumPost @relation(fields: [postId], references: [id], onDelete: Cascade)
  createdAt DateTime @default(now())

  @@unique([userId, postId])
  @@index([userId])
  @@index([postId])
}

model ForumReport {
  id           String             @id @default(cuid())
  reporterId   String
  reporter     User               @relation(fields: [reporterId], references: [id], onDelete: Cascade)
  postId       String?
  post         ForumPost?         @relation(fields: [postId], references: [id], onDelete: Cascade)
  commentId    String?
  comment      ForumComment?      @relation(fields: [commentId], references: [id], onDelete: Cascade)
  reason       ForumReportReason
  description  String?            @db.Text
  status       ForumReportStatus  @default(PENDING)
  createdAt    DateTime           @default(now())
  resolvedAt   DateTime?
  resolvedById String?
  resolvedBy   User?              @relation(fields: [resolvedById], references: [id], onDelete: SetNull)

  @@index([status])
  @@index([postId])
  @@index([commentId])
  @@index([reporterId])
}
```

### 1.3 Backend Route File

Create `backend/src/routes/forum.routes.js`:

**Router structure:**
```
/forum
  GET    /categories                     -> public (auth required, all roles)
  GET    /posts                          -> paginated list with search, category filter
  POST   /posts                          -> create post (with optional file upload)
  GET    /posts/:id                      -> single post
  PATCH  /posts/:id                      -> edit own post
  DELETE /posts/:id                      -> soft-delete own post (set status=DELETED)
  POST   /posts/:id/comments             -> add comment
  GET    /posts/:id/comments             -> get comments (paginated, threaded)
  PATCH  /comments/:id                   -> edit own comment
  DELETE /comments/:id                   -> delete own comment
  POST   /posts/:id/upvote               -> toggle upvote
  POST   /posts/:id/bookmark             -> toggle bookmark
  POST   /posts/:id/report               -> report post
  POST   /comments/:id/report            -> report comment
  GET    /my-posts                       -> current user's posts
  GET    /bookmarks                      -> current user's bookmarks
  GET    /reports                        -> admin/mod reports (ADMIN, SUPER_ADMIN)
  PATCH  /reports/:id/resolve            -> resolve report (ADMIN, SUPER_ADMIN)
  PATCH  /posts/:id/moderate             -> hide/restore post (ADMIN, SUPER_ADMIN)
  PATCH  /comments/:id/moderate          -> remove/restore comment (ADMIN, SUPER_ADMIN)
  GET    /stats                          -> forum stats for admin dashboard
```

**Key patterns:**
- All routes use `authenticate` middleware (no public/unauthenticated forum access)
- Validation via Zod schemas + `validate()` middleware
- File uploads via `uploadForumAttachment` (multer: 5MB images, 10MB PDF, max 5 files)
- Uses existing `storageService` for file uploads
- Uses existing `notify()` function from notification.routes.js for reply/moderation notifications
- Pagination: `?page=1&limit=20` with cursor-based option for infinite scroll
- Search: MySQL `LIKE` on title + content (with proper indexing)
- Soft-delete for posts/comments (status field, not actual deletion)

**File upload handling:**
- Accept: image/jpeg, image/png, image/webp (5MB max), application/pdf (10MB max)
- Max 5 attachments per post
- Upload via `storageService.uploadFile()` with `forumAttachments` folder
- Store metadata in `ForumPostAttachment`

**Moderation:**
- Admin + SUPER_ADMIN can: hide/restore posts, remove/restore comments, resolve reports
- Uses existing `requireRoles('ADMIN')` and `requireRoles('SUPER_ADMIN')` middleware
- SUPER_ADMIN supersedes ADMIN via existing hierarchy

**Notifications (integration with existing system):**
- When someone replies to a post -> notify post author
- When someone replies to a comment -> notify parent comment author
- When a post is hidden/removed -> notify post author
- When a report is resolved -> notify reporter
- Uses existing `notify()` function, creates `Notification` records directly

## PHASE 5: Upvotes/Bookmarks

Already covered in Phase 2. Key implementation details:

### Upvote Toggle
- POST `/api/forum/posts/:id/upvote` -> if exists, remove; if not, create
- Uses `@@unique([userId, postId, type])` constraint
- Optimistic update on frontend (increment/decrement count immediately)
- Backend returns `{ upvoted: boolean, upvoteCount: number }`

### Bookmark Toggle
- POST `/api/forum/posts/:id/bookmark` -> if exists, remove; if not, create
- Uses `@@unique([userId, postId])` constraint

## PHASE 6: Search/Pagination

Already covered in Phase 2. Key implementation details:

### Search
- Backend: `WHERE (title LIKE ? OR content LIKE ?)` with parameterized queries
- MySQL full-text search or LIKE with index support
- Search across: title, content, category name, author name

### Pagination
- Query params: `?page=1&limit=20`
- Backend: `skip` and `take` with Prisma
- Response includes: `{ posts: [], pagination: { page, limit, total, totalPages } }`
- Frontend: Page navigation buttons + "Load More" option

## PHASE 7: Reports/Moderation

Already covered in Phase 2. Key implementation details:

### Report Flow
- User clicks "Report" -> Modal with reason select + optional description
- Creates `ForumReport` record with status PENDING
- Admin/Super Admin sees reports in dashboard

### Moderation Actions
- Hide post: sets `status = HIDDEN` (post invisible to non-admins)
- Restore post: sets `status = PUBLISHED`
- Remove comment: sets `status = REMOVED` (comment invisible)
- Restore comment: sets `status = PUBLISHED`
- Resolve report: sets `status = RESOLVED` + `resolvedAt`

### Admin Dashboard Integration
- Add "Forum Moderation" section to existing Admin and Super Admin dashboards
- Show: Reports count, Pending count, Resolved count
- Table of reported items with actions

## Security

- All routes require authentication (`authenticate` middleware)
- Users can only edit/delete their own content
- Admin moderation uses existing `requireRoles()` middleware
- Input validation via Zod on all endpoints
- Content sanitized (no HTML injection)
- File type and size validated on upload
- SQL injection prevented by Prisma parameterized queries
- Unique constraints prevent duplicate reactions/bookmarks

- `ForumBookmark.userId+postId`
- `ForumReport.status`
- Server-side pagination (20 posts per page)
- Server-side search (MySQL LIKE with index)
- Select/include only required fields in queries
- Optimistic updates for upvotes/bookmarks on frontend
